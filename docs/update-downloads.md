# 更新下载与恢复

Workbench 在用户数据目录的 `update-downloads/` 中保留下载前缀。缓存身份绑定版本、平台、架构、文件名、长度及目录 SHA-256，不依赖随机本机 feed URL 或临时下载链接。重新下载仍从 Cloud 的稳定产物入口请求，因而重新获得重定向地址。

下载从本地实际长度发送单范围 `Range`；仅接受与偏移和已验证总长度完全一致的 `206 Content-Range`。源站忽略范围返回 `200` 时截断重下，绝不追加完整响应。断网、暂停或应用退出保留前缀；继续或重启后再次点击下载复用前缀。新产物开始下载时清理旧身份缓存，只保留一个包。完成后核对完整长度与 SHA-256，哈希错误删除缓存并拒绝安装。

下载服务先缓存元数据引用且符合平台格式的包，再通过本机 feed 提供已验证文件给原生更新器，保留其 SHA-512 和操作系统安装校验。网络进度不会被后续本地读取覆盖。网络中断后按 1、2、4 秒间隔自动续传重试，最多重试 3 次，耗尽后才报告失败；校验或磁盘错误直接报告。重试等待也能暂停，暂停等待本次任务收束后发布 paused；继续不会与旧任务并发写同一缓存。

网络传输达到 100% 后显示 verifying，SHA-256 校验完成后显示 preparing，由原生更新器继续校验、解压并准备安装。准备期间不提供暂停。Windows 在发布 downloaded 前启动并确认独立更新进程就绪，IPC 不阻止应用退出；正常关闭或父进程退出后，由独立进程等待文件释放并替换目录，不依赖退出事件里临时启动子进程。立即重启先发送重启标志，再关闭应用；未点击立即重启时只安装、不重新打开窗口。

共享下载层覆盖 Windows ZIP、macOS ZIP 和 Linux AppImage；原生安装仍由各平台既有更新器完成。当前回归在 Windows 上运行 HTTP 断开、暂停、范围回退、坏范围、坏摘要及服务重建续传；macOS/Linux 原生安装与打包升级须在对应平台另行验收。
