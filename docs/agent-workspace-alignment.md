# Agent 项目工作区对齐差量

Workbench 的 Agent 宿主围绕代码增强装配标准 Node、项目代码能力、浏览器调试与按需记忆。
共享运行循环和模型能力合同继续由 Platform 负责，Workbench 负责 Electron 执行宿主、项目归属、IPC 与界面。

## 合同与已有行为

| 变化 | 理由 | 影响 |
| --- | --- | --- |
| 公共执行依赖改用 `@velaros-ai/velaros/execution`，会话使用标准 Node | 与 Platform 当前公开出口及 Desktop 执行语义一致 | 原生 ESM、标准 npm 包、stdout/stderr 与退出状态可用；进程停止和项目归属经过真实执行验证。 |
| 项目会话装配 `velaros:sessions`，新增会话目录与交接回执 IPC | 代码任务可以在当前项目会话之间协作，保留独立上下文与改动归属 | `ask` 按输入身份等待结果，`tell` 顺序排队；循环等待拒绝，关闭项目撤销等待，失败显示到来源会话。新会话沿用已批准的模型、权限与沙箱配置。 |
| 新增 Agent 后台进程 IPC 与聊天顶部入口 | 用户需要查看和控制 Agent 启动的开发服务器及交互式命令 | 按启动项目及会话读取输出、输入、中断和停止；同名会话和改变 cwd 的命令仍按启动项目隔离。 |
| 会话组合增加可选 `SessionActions` 顶部工具入口 | 进程和工作笔记属于当前会话，集中放在新建会话按钮左侧 | 宿主按当前会话装配两个入口，浮层向下展开；切换会话重建工具状态。 |
| 发送准备与登录状态按发起会话持有 | 登录或读取附件期间用户可切换聊天 | 输入仍交给原会话；新会话的输入、草稿与登录等待独立，重复提交由会话预占控制。 |
| 草稿上下文按项目与会话保存，文件投递增加 `targetSessionId` | 文件引用、页面选区和执行选项应跟随各自聊天 | 切换会话保留代码上下文；文件与浏览器投递按目标会话接收；发送准备期间新增的文字、附件与引用继续保留。 |
| 队列携带完整上下文并等待主进程接纳 | 排队期间用户可以继续编辑，投递也可能被拒绝 | 入队时复制当前文件、引用、页面选区、思考深度、计划和目标模式；失败保留重试，出队保留新草稿，删除会话忽略迟到回执。 |
| 持久化运行状态，未收尾历史恢复为已中断 | 应用重启后上次执行已经结束，用户需要可续接的状态 | running、stopping 和等待交互的历史恢复为 aborted；已有错误继续显示，下一条输入归入原任务。旧历史缺少运行状态时根据起止时间恢复。 |
| 笔记 IPC 完整注销 | 宿主退出和重新装配应释放读取入口 | list-notes/read-note 与变更监听一起清理。 |
| send 请求增加可选 `sandbox` | 每轮固定项目写入范围 | 沙箱默认关闭；排队与会话交接继续携带执行配置，主进程按当前项目核对。 |
| 项目、语言查询与浏览器调试直接进入能力目录 | 代码任务按需要发现合同并调用 | `residentModules: []` 保持能力合同按需读取；项目写入沿用 Kernel 效果闸，浏览器操作连接当前会话页面。 |
| 标准 Node 环境公开代码工具包 | 重构、格式化、结构搜索和网页测试可直接使用原包 API | 运行环境只读取版本和解析目录，Node 到 import 时才加载实现；工作区安装的依赖优先。 |
| 会话 IPC 增加 list-notes/read-note/notes-changed | 用户查看 Platform 原始工作笔记与当前版本 | 请求验证项目归属及分页上限；入口关闭或会话切换取消旧读取，正文按确定版本读取。 |
| 脚本通知增加可选 language/processOutput/processOutputTruncated | 原生程序可能只有进程输出，仍需显示并保存 | 旧历史缺省字段继续读取；新输出映射为共享 UI 执行回执，重开历史时保留。 |
| 长期记忆由开场索引改为按需 recall | 与 Desktop 当前上下文装配一致 | 设置与数据作用域保持按项目划分，模型用到时才读取正文。 |
| 权限档按整段程序审批，沙箱另设开关 | Node 程序可调用原生文件/进程 API，确认完整程序才能覆盖执行内容 | “每次询问”确认程序及项目写入；标准直接执行；默认沙箱关闭，与 Desktop 相同。对应 README、设置说明及集成验收一起更新。外部引擎继续按自己的审批协议执行。 |
| 发行包交付标准 Node 与统一 `node-runtime/node_modules`，React 放入运行依赖 | Agent 代码执行使用固定、完整的工具依赖 | 运行装配与发行流程共用代码工具包名表；打包复制依赖闭包并核验资源字节、版本和原包行为，类型声明按清单保留。 |
| 本地 package:dir 明确关闭强制签名 | 本地候选包使用空签名身份，需与打包器签名要求一致 | 本地目录构建可完整结束；正式 macOS 打包继续遵守发行签名配置。 |

## 验收

会话 Node 集成测试覆盖原生执行、IDE 写入归属、权限拒绝、沙箱越界、按需长期记忆、能力发现、
笔记版本与通知、停止模型与进程。普通项目会话直接验证 JS/TS 诊断及五个代码工具的 npm 导入；
另一个工作区依赖夹具通过导入副作用证明目录发现只读元数据，实际调用才执行实现，并使用项目版本。

界面数据测试覆盖笔记分页、会话切换取消、执行输出历史。会话协作覆盖真实 Node 交接、准确结果回传、
顺序排队、项目范围与互相等待；后台进程使用真实可交互子进程验证输出、输入、停止和跨项目隔离。
草稿与队列测试覆盖上下文深拷贝、编辑和排序后的投递、失败重试、异步准备时新增草稿保留、目标会话投递、
删除会话后的迟到回执，以及带状态和仅有起止时间的历史恢复。

本轮交付核验：

- `bun run check` 通过：1480 个单元测试（210 个文件）、29 个 Node 集成与发行测试，以及类型、lint、产品边界、包锁、运行探针和构建预算。
- Platform 的 `bun run check:module-ownership` 通过。
- macOS arm64 候选包构建及 afterPack 资源门禁通过：核验 8 个外部 ESM 包、标准 Node/npm 与代码工具依赖的完整文件和版本。发行 Node 实际执行跨文件重命名、TS/TSX 格式化、JSONC 注释保留、结构搜索和 Playwright 导入。
- 隐藏 Electron 实例从真实 ASAR 加载主进程、preload 与 renderer，核对输入菜单、AI 设置和两个顶部工具的位置；使用独立 Git 项目与受控发送回执验证队列接纳、拒绝重试、文件引用和计划模式快照、新草稿保留、切换会话，以及重启后的中断续接。
- 集成模型采用确定性测试驱动；界面验收使用发送回执夹具，真实原生进程执行与控制由 Node 集成测试及发行资源门禁覆盖。
