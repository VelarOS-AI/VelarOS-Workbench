## 项目切换与资源准入边界

已读实际 WindowManager、ProjectHub/IPC、RecentProjectsStore、ProjectRegistry、main 资源释放组合及 renderer 切换/退出入口。
发现同窗 A→B 与 A→C 可同时释放 A，随后 C 覆盖 B 而未释放 B；释放 helper 吞错，Promise.all 又可能在其他 owner
尚未收束时提前拒绝。退出还在清理之前清空原项目状态。

每窗 record 的队列负责串行切换，实际退役状态负责准入，Hub 仍是项目根的唯一权威。
释放任务均被登记，等待全部 settle 后才聚合失败；失败不会伪装成退出或新根发布，原始错误保留诊断。
发布前重核窗口仍存在及目标未被别窗占用。窗口关闭时先启动释放回调，再请求最后窗口退出。

Terminal/Debug/Language、命令/搜索/Watch/Workspace、Conversation/Peer/Console input/Browser 的新增工作，
在首个 await 前调用同一同步项目准入，再沿原 pending/symbol/project lease 登记；局部 close 不再提前重开整体入口。
注册时必须提供真实 WindowManager，不用 optional/no-op 门。停止、取消、回答、既有句柄读取和 peer 回执保留。
项目根沿现有 resolve 等价合同，没有顺便更改路径身份或加 realpath 兜底。

本批不声称等待全部旧文件操作完成：普通 FS 写、replaceContent 独立 worker、已开始的短目录/文件列举，
以及已准入 inline-completion provider 请求没有新增总 registry 或收束协议。它们仍沿原生命周期，不能把新增准入当作全量关闭证明。
